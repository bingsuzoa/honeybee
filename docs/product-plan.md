# 신혼부부 대출 비교 계산기 기획서

## 1. 문서 목적

이 문서는 `신혼부부 대출 비교 계산기`의 제품 방향, MVP 범위, 기능 요구사항, 데이터 구조, 계산/판단 로직, 화면 구성, 개발 기준을 정의한다.

본 문서를 기준으로 웹 애플리케이션 프로젝트를 생성하고, 초기 MVP를 구현할 수 있어야 한다.

## 2. 서비스 개요

### 2.1 서비스명

신혼부부 대출 비교 계산기

### 2.2 한 줄 설명

신혼부부가 주택 구입 시 이용 가능한 주요 주택담보대출 상품을 비교하고, 입력 조건 기준으로 가장 적합한 대출 후보를 계산해주는 서비스.

### 2.3 핵심 가치

사용자는 여러 정부/금융기관 사이트를 직접 확인하지 않아도 자신의 조건을 입력해 다음 정보를 확인할 수 있다.

- 이용 가능한 대출 상품
- 이용 불가능한 대출 상품과 사유
- 예상 금리
- 최대 대출 가능 금액
- 월 납입금
- 총 상환금액
- 총 이자
- 가장 적합한 대출 1개
- 추천 근거와 공식 문서 출처

### 2.4 제품 성격

본 서비스는 AI 상담 서비스가 아니다.

초기 MVP는 다음 성격의 서비스로 구현한다.

- 공식 URL 기반 대출 정보 수집 서비스
- 신혼부부 대상 대출 조건 비교 서비스
- 규칙 기반 자격 판단 서비스
- 대출 상환 계산기
- 추천 근거 제공 서비스

RAG는 최종 판단을 직접 수행하는 용도가 아니라, 공식 문서 근거 검색과 출처 제공을 위해 사용한다.

## 3. 문제 정의

신혼부부가 주택 구입을 준비할 때 대출 선택이 어렵다.

주요 어려움은 다음과 같다.

- 정책대출과 은행대출의 조건이 다르다.
- 소득, 자산, 주택가격, 면적, 생애최초 여부 등 확인해야 할 조건이 많다.
- 금리가 낮아도 한도가 부족하면 사용할 수 없다.
- 월 납입금과 총 이자를 직접 계산하기 어렵다.
- 공식 사이트 문서를 읽어도 자신에게 해당되는지 판단하기 어렵다.
- 여러 상품을 한 화면에서 비교하기 어렵다.

이 서비스는 위 문제를 해결하기 위해 사용자의 조건을 입력받고, 등록된 공식 대출 정보를 기반으로 가장 적합한 대출 후보를 계산한다.

## 4. 서비스 대상

### 4.1 MVP 대상 사용자

초기 MVP는 다음 사용자를 대상으로 한다.

- 혼인신고를 완료한 신혼부부
- 주택 구입을 계획 중인 신혼부부
- 정책대출과 은행 주택담보대출을 비교하고 싶은 사용자
- 대출 신청 전 대략적인 가능 여부와 비용을 확인하고 싶은 사용자

### 4.2 MVP에서 우선하지 않는 사용자

초기 MVP에서는 다음 사용자를 주요 대상으로 삼지 않는다.

- 일반 무주택자 전체
- 1인 가구
- 기존 주택 보유자
- 대환대출 목적 사용자
- 전세자금대출 사용자
- 사업자 대출 사용자
- 신용대출 사용자

## 5. MVP 목표

### 5.1 제품 목표

사용자가 신혼부부 관련 기본 조건을 입력하면, 서비스가 주요 주택담보대출 상품을 비교하여 가장 적합한 대출 1개를 추천한다.

### 5.2 MVP 완료 기준

MVP는 다음 조건을 만족하면 완료로 본다.

- 사용자가 신혼부부 대출 판단에 필요한 정보를 입력할 수 있다.
- 필수 선택값에 대한 유효성 검사를 수행한다.
- 관리자가 공식 URL을 등록할 수 있다.
- 등록된 URL의 페이지 내용을 수집해 문서 저장소에 적재할 수 있다.
- 등록된 대출 상품의 구조화된 조건 데이터를 관리할 수 있다.
- 주요 대출 상품의 가능/불가능 여부를 판단할 수 있다.
- 불가능한 상품에 대해 사유를 제공할 수 있다.
- 월 납입금, 총 상환금액, 총 이자를 계산할 수 있다.
- 후보 대출 상품을 비교할 수 있다.
- 가장 적합한 대출 1개를 추천할 수 있다.
- 추천 근거를 제공할 수 있다.
- 공식 문서 출처를 함께 표시할 수 있다.

## 7. 비교 대상 대출 상품

초기 MVP의 비교 대상은 다음으로 제한한다.

### 7.1 신혼부부 디딤돌대출

- 정책대출
- 신혼부부 조건 판단 필요
- 생애최초 여부에 따라 조건이 달라질 수 있음
- 소득, 자산, 주택가격, 면적, 무주택 여부 판단 필요

### 7.2 보금자리론

- 정책성 장기 고정금리 주택담보대출
- 소득, 주택가격, 대출한도 등 조건 판단 필요
- 디딤돌대출과 함께 비교 대상

### 7.3 일반 은행 주택담보대출

- 은행별 상품
- 금리와 한도 정보는 관리자가 입력하거나 공식 URL 기반으로 관리
- 세부 심사 결과가 아니라 예상 비교용으로 제공

### 7.4 집단 잔금대출

- 민간분양/분양아파트 관련 대출
- 상품 조건은 단지/은행별로 다를 수 있음
- MVP에서는 관리자가 입력한 상품 데이터 기준으로 비교

## 8. 사용자 조건 선택 항목

### 8.0 조건 선택 UX 원칙

사용자 화면에서는 직접 입력을 최소화하고, 가능한 항목은 선택형 UI로 제공한다.

대출 계산기는 입력해야 할 정보가 많기 때문에 사용자가 금액과 날짜를 직접 입력하는 방식은 피로도가 높다. 따라서 MVP에서는 다음 원칙을 적용한다.

- boolean 값은 토글 또는 선택 버튼으로 제공한다.
- enum 값은 세그먼트 컨트롤, 라디오, 드롭다운으로 제공한다.
- 금액 값은 직접 입력보다 금액 구간 선택 또는 슬라이더를 우선한다.
- 날짜 값은 직접 입력보다 연/월 선택 또는 기간 선택을 우선한다.
- 면적 값은 대표 면적 선택 버튼을 우선하고, 필요 시 직접 입력을 보조 옵션으로 제공한다.
- 사용자가 정확한 값을 모르는 경우에도 대략적인 결과를 볼 수 있어야 한다.
- 내부 계산과 자격 판단에는 선택값을 정규화한 숫자/날짜 값을 사용한다.

선택형 입력의 목적은 사용자의 입력 부담을 줄이는 것이다. 다만 대출 자격 판단은 기준값 경계에서 결과가 달라질 수 있으므로, 금액과 날짜는 `정확히 입력하기` 옵션을 보조로 제공할 수 있다.

### 8.5 선택값 정규화

사용자 화면의 선택값은 내부 분석 API로 전달되기 전에 정규화한다.

예시:

| UI 선택값 | 내부 표현 예시 |
| --- | --- |
| 부부합산 연소득 `6천~8천만원` | `{ "min": 60000000, "max": 80000000, "representative": 70000000 }` |
| 주택가격 `5억~6억원` | `{ "min": 500000000, "max": 600000000, "representative": 550000000 }` |
| 혼인 기간 `3~5년` | `{ "minYears": 3, "maxYears": 5 }` |
| 전용면적 `60~84m2` | `{ "min": 60, "max": 84, "representative": 84 }` |

정확한 금액이 필요한 자격 기준 근처에서는 서비스가 `정확한 금액을 입력하면 더 정확히 판단할 수 있어요`라는 보조 안내를 표시할 수 있다.

## 9. 선택값 검증

### 9.1 공통 검증

- 필수값 누락 불가
- 선택형 항목은 허용된 선택지 내 값이어야 함
- 직접 입력 보조 옵션을 사용하는 경우 숫자 항목은 음수 입력 불가
- 직접 입력 보조 옵션을 사용하는 경우 날짜는 유효한 날짜 형식이어야 함
- 필요한 대출금액은 주택가격보다 클 수 없음
- 대출기간은 허용된 선택지 내 값이어야 함
- 전용면적은 허용된 선택지 또는 0보다 큰 직접 입력값이어야 함

### 9.2 도메인 검증

- 부부합산 연소득이 선택되지 않은 경우 본인 연소득과 배우자 연소득 선택값을 정규화해 합산한다.
- 필요한 대출금액이 각 상품의 최대 가능 금액보다 큰 경우 `한도 부족`으로 표시한다.
- 혼인 여부가 기혼이 아닌 경우 MVP에서는 `신혼부부 전용 판단 불가` 메시지를 표시한다.
- 사용자가 `잘 모르겠음`을 선택한 항목은 보수적인 기본값을 적용하거나, 결과 화면에 `정확도 낮음` 안내를 표시한다.

## 10. 데이터 수집 및 RAG 전략

### 10.1 기본 원칙

서비스는 웹 전체를 검색하지 않는다.

관리자가 등록한 공식 URL만 수집한다.

### 10.2 수집 대상

- 정부기관 공식 사이트
- 공공기관 공식 사이트
- 금융기관 공식 홈페이지
- 상품 안내 페이지
- 금리 안내 페이지
- 자격 조건 안내 페이지

### 10.3 수집 제외 대상

- 블로그
- 카페
- 커뮤니티
- 뉴스 기사
- 광고성 랜딩 페이지
- 출처가 불명확한 문서

### 10.4 RAG 역할

RAG는 다음 목적에 사용한다.

- 수집 문서 검색
- 상품 조건의 근거 문장 조회
- 추천/불가 사유의 출처 제공
- 관리자 검수 보조
- 정책 문서 변경 사항 확인 보조

RAG는 다음을 직접 수행하지 않는다.

- 최종 자격 판정
- 최종 한도 계산
- 최종 월 납입금 계산
- 최종 추천 순위 산정

### 10.5 권장 데이터 흐름

```text
관리자 URL 등록
↓
페이지 크롤링
↓
본문 추출
↓
문서 청크 분리
↓
임베딩 생성
↓
벡터 저장소 적재
↓
관리자/시스템이 조건 근거 검색
↓
구조화된 상품 조건 데이터 관리
↓
규칙 엔진으로 사용자 조건 판단
↓
결과 화면에서 공식 출처 표시
```

## 12. 자격 판단 로직

### 12.1 판단 원칙

각 대출 상품은 다음 순서로 판단한다.

1. 상품 활성 여부 확인
2. 혼인/신혼부부 조건 확인
3. 무주택 조건 확인
4. 소득 조건 확인
5. 자산 조건 확인
6. 주택가격 조건 확인
7. 전용면적 조건 확인
8. 대출한도 계산
9. 필요한 대출금액 충족 여부 확인

### 12.2 불가능 사유 예시

- 신혼부부 조건을 충족하지 않습니다.
- 무주택 요건을 충족하지 않습니다.
- 부부합산 연소득 기준을 초과했습니다.
- 순자산 기준을 초과했습니다.
- 주택가격 기준을 초과했습니다.
- 전용면적 기준을 초과했습니다.
- 필요한 대출금액이 최대 가능 금액보다 큽니다.
- 해당 상품은 선택한 상환방식을 지원하지 않습니다.

### 12.3 신혼부부 판단

MVP에서는 신혼부부 판단 기준을 구조화 데이터로 관리한다.

예시 필드:

- 혼인신고일 기준 N년 이내
- 결혼 예정자 포함 여부
- 자녀 수에 따른 조건 완화 여부

정확한 기준값은 관리자가 공식 URL을 확인한 뒤 `LoanEligibilityRule`에 입력한다.

## 13. 대출 계산 로직

### 13.1 원리금균등 상환

매월 동일한 금액을 상환하는 방식.

계산식:

```text
월 이자율 = 연이자율 / 12
총 납입 개월 수 = 대출기간(년) * 12
월 납입금 = 원금 * 월이자율 * (1 + 월이자율)^개월수 / ((1 + 월이자율)^개월수 - 1)
총 상환금액 = 월 납입금 * 개월수
총 이자 = 총 상환금액 - 원금
```

연이자율이 0인 경우:

```text
월 납입금 = 원금 / 개월수
총 상환금액 = 원금
총 이자 = 0
```

### 13.2 원금균등 상환

매월 동일한 원금을 상환하고, 남은 원금에 대한 이자를 추가로 납부하는 방식.

계산식:

```text
매월 상환 원금 = 원금 / 개월수
월별 이자 = 남은 원금 * 월이자율
월별 납입금 = 매월 상환 원금 + 월별 이자
총 상환금액 = 모든 월별 납입금 합계
총 이자 = 총 상환금액 - 원금
```

결과 화면에서는 원금균등의 경우 첫 달 납입금과 평균 월 납입금을 함께 표시할 수 있다.

## 14. 추천 점수 산정

### 14.1 기본 원칙

추천은 가능한 대출 상품만 대상으로 한다.

단, 한도가 부족한 상품은 `이용 가능하나 필요한 금액 부족` 상태로 표시하고 추천 1순위에서는 제외한다.

### 14.2 추천 우선순위

1. 자격 충족
2. 필요한 대출금액 충족
3. 총 이자 낮음
4. 월 납입금 낮음
5. 금리 낮음
6. 중도상환수수료 부담 낮음
7. 정책대출 우선

### 14.3 점수 예시

MVP에서는 다음과 같은 가중치 기반 점수를 사용할 수 있다.

| 요소 | 점수 |
| --- | --- |
| 자격 충족 | 30 |
| 필요한 대출금액 충족 | 25 |
| 총 이자 경쟁력 | 20 |
| 월 납입금 경쟁력 | 10 |
| 금리 경쟁력 | 10 |
| 중도상환수수료 부담 낮음 | 5 |

점수 산정 방식은 구현 단계에서 함수로 분리하고, 추후 조정 가능하게 한다.

### 14.4 추천 문구 예시

- 현재 입력 조건에서는 `신혼부부 디딤돌대출`이 가장 적합합니다.
- 부부합산소득, 주택가격, 전용면적 기준을 충족합니다.
- 필요한 대출금액을 충족하며, 후보 상품 중 총 이자가 가장 낮습니다.
- `보금자리론`도 이용 가능하지만 예상 총 이자가 더 높습니다.

## 15. 화면 구성

### 15.1 사용자 조건 선택 화면

목적: 사용자가 신혼부부 대출 판단에 필요한 정보를 가능한 한 선택형으로 제공한다.

구성:

- 기본 정보 섹션
- 소득/자산 섹션
- 주택 정보 섹션
- 대출 조건 섹션
- 계산하기 버튼

UX 기준:

- 직접 입력 필드는 기본으로 노출하지 않는다.
- 금액은 구간 선택, 슬라이더, 대표 금액 버튼을 우선 사용한다.
- 날짜는 혼인 기간 선택을 우선 사용하고, 정확한 혼인신고일은 보조 옵션으로 제공한다.
- 면적은 대표 면적 선택을 우선 사용한다.
- 사용자가 잘 모르는 항목에는 `잘 모르겠음` 선택지를 제공한다.
- 선택값이 자격 기준 경계에 걸리는 경우 정확도 안내를 표시한다.
- 필수 선택 누락 시 즉시 안내한다.
- 직접 입력 보조 옵션을 사용하는 경우 숫자는 콤마 포맷을 지원한다.
- 결과 계산 전 개인정보 저장 여부를 요구하지 않는다.

### 15.2 결과 요약 화면

목적: 사용자가 가장 중요한 답을 먼저 확인한다.

상단에 표시할 정보:

- 가장 적합한 대출 상품명
- 추천 요약 문장
- 예상 금리
- 최대 가능 금액
- 월 납입금
- 총 이자
- 총 상환금액
- 주요 추천 근거

### 15.3 후보 비교표

목적: 여러 상품을 한눈에 비교한다.

비교 항목:

- 상품명
- 기관/은행명
- 가능 여부
- 불가능 사유
- 예상 금리
- 최대 가능 금액
- 필요한 금액 충족 여부
- 월 납입금
- 총 이자
- 총 상환금액
- 중도상환수수료
- 순위

### 15.4 공식 출처 영역

목적: 결과의 신뢰도를 높인다.

표시 항목:

- 출처 제목
- 기관/은행명
- URL
- 수집일
- 관련 근거 요약

### 15.5 관리자 URL 관리 화면

목적: 관리자가 공식 URL을 등록하고 수집 상태를 관리한다.

구성:

- URL 등록 폼
- 상품 연결 선택
- 출처 유형 선택
- 등록 URL 목록
- 수집 상태
- 마지막 수집일
- 재수집 버튼

## 16. 기능 요구사항

### FR-01 사용자 조건 선택

사용자는 신혼부부 대출 비교에 필요한 정보를 선택형 UI로 제공할 수 있어야 한다.

직접 입력은 금액, 날짜, 면적 등 정확한 판단이 필요한 항목의 보조 옵션으로만 제공한다.

### FR-02 선택값 검증

서비스는 필수 선택값, 허용된 선택지, 직접 입력 보조값, 날짜, 금액 범위 등 입력값 유효성을 검사해야 한다.

### FR-03 공식 URL 등록

관리자는 대출 정보 수집에 사용할 공식 URL을 등록할 수 있어야 한다.

### FR-04 페이지 수집

서비스는 등록된 URL의 페이지 본문을 수집할 수 있어야 한다.

### FR-05 문서 인덱싱

서비스는 수집된 문서를 청크로 분리하고 검색 가능한 형태로 저장해야 한다.

### FR-06 대출 상품 관리

서비스는 대출 상품의 기본 정보, 금리, 한도, 조건을 구조화 데이터로 관리해야 한다.

### FR-07 대출 자격 판단

서비스는 사용자의 선택값을 정규화한 분석 입력값과 상품 조건을 비교하여 대출 가능 여부를 판단해야 한다.

### FR-08 불가능 사유 제공

대출이 불가능한 경우 서비스는 구체적인 사유를 제공해야 한다.

### FR-09 대출 비용 계산

서비스는 각 상품의 월 납입금, 총 상환금액, 총 이자를 계산해야 한다.

### FR-10 상품 비교

서비스는 후보 대출 상품을 동일 기준으로 비교할 수 있어야 한다.

### FR-11 최적 대출 추천

서비스는 가능한 상품 중 가장 적합한 대출 1개를 추천해야 한다.

### FR-12 추천 근거 제공

서비스는 추천된 상품의 선정 근거를 제공해야 한다.

### FR-13 공식 출처 제공

서비스는 추천/판단 결과와 관련된 공식 출처를 함께 제공해야 한다.

### FR-14 예외 상황 처리

서비스는 다음 상황을 처리해야 한다.

- 이용 가능한 대출이 없는 경우
- 입력 정보가 부족한 경우
- 대출 한도가 부족한 경우
- 공식 URL 수집에 실패한 경우
- 상품 조건 데이터가 부족한 경우

## 17. 비기능 요구사항

### 17.1 신뢰성

- 결과는 공식 URL과 구조화된 규칙을 기반으로 제공해야 한다.
- 최종 대출 승인 가능성을 보장하지 않는다는 안내를 제공해야 한다.
- 수집일과 출처를 표시해야 한다.

### 17.2 성능

- 사용자 계산 결과는 일반적인 입력 기준 3초 이내에 반환하는 것을 목표로 한다.
- URL 크롤링은 비동기 작업으로 처리할 수 있다.

### 17.3 보안/개인정보

- MVP에서는 사용자 계정을 만들지 않는다.
- 사용자의 선택값과 정규화된 분석 입력값은 결과 계산을 위해서만 사용한다.
- 사용자의 주민등록번호, 신용점수, 직장명 등 민감정보는 입력받지 않는다.

### 17.4 유지보수성

- 상품 조건과 계산 로직은 분리한다.
- 대출 상품 추가가 가능하도록 상품 데이터 모델을 일반화한다.
- 추천 점수 가중치는 코드 내 상수 또는 설정값으로 분리한다.

## 24. 핵심 결정 사항

- 서비스명은 `신혼부부 대출 비교 계산기`로 한다.
- MVP 대상은 신혼부부로 제한한다.
- AI 상담 기능은 구현하지 않는다.
- RAG는 공식 문서 근거 검색과 출처 제공에 사용한다.
- 자격 판단은 구조화된 규칙 엔진으로 수행한다.
- 추천 결과는 가장 적합한 대출 1개를 먼저 보여준다.
- 후보 상품 비교표를 함께 제공한다.
- 대출 신청/중개 서비스로 포지셔닝하지 않는다.
